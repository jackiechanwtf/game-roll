# Game Roll

Небольшой сервис для компании друзей: выбирает случайную ПК-игру, сохраняет принятые игры и показывает общую историю с потраченными часами и комментариями. Интерфейс рассчитан на компьютеры и ноутбуки.

## Как пользоваться

1. Введи имя или ник. Чтобы продолжить с другого компьютера, выбери то же имя.
2. Укажи, сколько часов готов потратить на основной сюжет, и нажми «Выбрать игру».
3. Первую и вторую игру можно принять или перебросить. Третья принимается автоматически.
4. Принятая игра появится в общей таблице со статусом «Прохожу».
5. Закончив, нажми «Прошёл» или «Бросил», укажи потраченные часы и при желании напиши комментарий. Нажми «Сохранить результат».
6. Теперь можно выбрать следующую игру. Предыдущие записи останутся в истории.

Друзья видят общую таблицу, фильтруют её по игроку и статусу. Таблица обновляется каждые 15 секунд и по кнопке «Обновить». Уже выпавшие конкретному игроку игры, включая отклонённые, повторно не предлагаются. Разным игрокам может выпасть одна и та же игра.

В каталоге 500 ПК-игр с оценкой длительности основного сюжета. Источник, дата снимка, лицензия и правила отбора описаны в [DATA_SOURCES.md](DATA_SOURCES.md). Время приблизительное; прохождение на 100% может занять дольше.

## Установка и запуск после клонирования

Нужен Python **3.10 или новее**. CI проверяет Python 3.12. Отдельная база данных и ключи внешних API не требуются.

```bash
git clone https://github.com/jackiechanwtf/game-roll.git
cd game-roll
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app_final:app
```

В Windows вместо двух команд создания и активации окружения:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

Если PowerShell не разрешает активацию, можно выполнять команды через `.venv\Scripts\python.exe` напрямую.

- Приложение: http://127.0.0.1:8000
- Документация и интерактивная проверка API: http://127.0.0.1:8000/docs
- Работоспособность: http://127.0.0.1:8000/health
- Версия: http://127.0.0.1:8000/version

Для обычной работы используется команда без `--reload`, показанная выше. При разработке можно включить перезапуск после правок:

```bash
python -m uvicorn app_final:app --reload
```

Остановка сервера: `Ctrl+C` в терминале.

## Как открыть друзьям

Один человек запускает **один общий экземпляр** сервиса. Для компьютеров в одной локальной сети:

```bash
python -m uvicorn app_final:app --host 0.0.0.0 --port 8000
```

Друзья открывают `http://IP-КОМПЬЮТЕРА:8000`, где IP — локальный адрес компьютера с сервером. Адрес `127.0.0.1` работает только на самом компьютере с сервером. Доступ зависит от настроек сети и межсетевого экрана.

Для друзей из интернета сервис нужно разместить на доступном им хосте с постоянным диском. Публикация кода на GitHub сама по себе не запускает сайт. GitHub Pages не выполняет Python/FastAPI.

Вход устроен по имени без пароля: сервис рассчитан на небольшую компанию, где участники доверяют друг другу. Выбор имени не является проверкой личности. Любой участник, выбравший чужое имя, получит доступ к его действиям.

## Где сохраняются данные

- `catalogue.json` — готовый каталог, уже включённый в репозиторий.
- `data/state.json` — игроки, история выпавших игр, попытки, принятые игры, потраченные часы и комментарии. Создаётся автоматически при первом запуске.

Данные сохраняются после обновления страницы и перезапуска сервера. Для резервной копии остановите сервер и скопируйте `data/state.json`. Папка `data/` исключена из Git и CI artifact: личная история не попадает в публичный репозиторий.

Сервис работает **одним процессом**: не добавляйте `--workers 2` и не запускайте два сервера с одним файлом данных. Внутри одного процесса запись защищена блокировкой и заменой готового файла, поэтому одновременные действия друзей не затирают друг друга.

## Переменные окружения

Все настройки имеют значения по умолчанию. При необходимости скопируйте `.env.example` в `.env` и измените значения; файл читается при запуске.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GAMES_FILE` | `catalogue.json` | Откуда брать список игр и время прохождения; относительный путь считается от папки проекта |
| `GAME_ROLL_DATA` | `data/state.json` | Путь к файлу с игроками и историей; относительный путь считается от папки проекта |

После изменения настроек перезапустите сервер. Настоящий `.env` исключён из Git. Для запуска достаточно безопасного `.env.example`; пароли и токены приложению не нужны.

Например, чтобы использовать другой подготовленный список игр, сохраните его в формате `catalogue.json` и укажите путь в `.env`:

```dotenv
GAMES_FILE=my_games.json
GAME_ROLL_DATA=data/state.json
```

Приложение читает игры из этого JSON-файла. Готовый каталог уже лежит в проекте; подключаться к внешней базе или скачивать данные при запуске не нужно. `.venv` — это отдельная папка с Python-зависимостями, а `.env` — файл этих настроек.

## Тесты

В активированном окружении:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -v
```

Тесты используют отдельные временные файлы и маленький тестовый каталог. Ваша реальная история не меняется. Подробное объяснение тестов и CI — в [CI_AND_TESTS.md](CI_AND_TESTS.md).

## Основные маршруты

| Метод и путь | Назначение |
| --- | --- |
| `GET /games?max_hours=20` | Каталог с ограничением по времени |
| `GET /players` | Список участников |
| `POST /players` | Создать игрока или выбрать существующее имя |
| `GET /players/{id}/state` | Восстановить текущую игру и использованные попытки |
| `POST /rolls` | Начать выбор игры |
| `POST /rolls/{id}/reroll` | Использовать переброс |
| `POST /rolls/{id}/accept` | Принять предложенную игру |
| `GET /assignments` | Общая таблица игр, статусов и комментариев |
| `PATCH /assignments/{id}` | Завершить игру, сохранить потраченные часы и комментарий |

Тело запросов и примеры полей доступны в `/docs`. В запросах принятия и переброса передаётся номер текущей попытки `attempt`: действие из устаревшей вкладки не должно принимать другую игру или тратить следующий переброс.

## Проверка и диагностика

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
curl 'http://127.0.0.1:8000/games?max_hours=5'
```

Ожидаются `{"status":"ok"}` и `{"version":"1.0.0"}`. Логи видны в терминале с сервером: запуск и остановка, HTTP-запросы, предложение и принятие игры, изменение статуса. Текст комментариев в логи не записывается.

| Проблема | Что проверить |
| --- | --- |
| `No module named fastapi` | Активировано ли `.venv`, выполнена ли установка `requirements.txt` |
| `Address already in use` | Не запущен ли сервер в другом терминале; можно использовать `--port 8001` |
| Сайт не открывается | Сервер запущен и не завершился с ошибкой; адрес и порт совпадают с выводом Uvicorn |
| «Для трёх попыток нужно хотя бы 3 новые игры» | Увеличить лимит часов. Фильтр должен оставлять три ещё не выпадавшие игроку игры |
| Новый розыгрыш недоступен | Завершить выбор или отметить текущую игру пройденной/брошенной |
| Ошибка чтения JSON при запуске | Проверить `GAME_ROLL_DATA`, права и целостность файла; восстановить резервную копию. Повреждённая история автоматически не стирается |
| Друзья не видят друг друга | Все должны открывать один общий сервер, а не отдельные локальные копии |

## Структура

```text
app_final.py               # HTTP-маршруты, настройки, запуск и логи
game_service.py            # Правила выбора и принятия игры
storage.py                 # Сохранение состояния в JSON
catalogue.json             # 500 игр, готовых к использованию
static/                    # Одна HTML-страница, CSS и обычный JavaScript
scripts/prepare_catalogue.py # Повторная подготовка каталога, при необходимости
test_app.py                # Автоматические тесты
.github/workflows/ci.yml    # Автоматическая проверка и artifact
```
